## Проверка кнопок и аудит

`tools/buttons.mjs` открывает каждый экран под каждой ролью и нажимает каждую кнопку, ссылку, вкладку и пункт меню (изменяющие запросы подменяются заглушкой, данные не трогаются); статический аудит кода и живой обход дали список поправок, все сделаны. Осознанно оставлены решения заказчика: read-only справочники и воронки для KAM/HEAD без пункта меню (S2-3); правило «недоступно вашей роли» реализовано не везде (S2-5); диалог перехода теряет черновик при переходе по подсказке-ссылке (S2-12); разрыв с исходным кейсом — отчёты без периода и фильтров по вузу, направлению, продукту, импорт не заводит карточку «лицензия вуза ↔ вендор ↔ ПО» (см. корневой `README.md` → «Соответствие требованиям кейса»).

## Что готово

* **Каркас**: SvelteKit 2 SPA, Svelte 5, TS strict, Tailwind v4 поверх дизайн-системы rt-ui (токены вшиты в тему), 4 темы, шрифт Rostelecom Basis, типизированный клиент по OpenAPI (210 операций), RFC 7807, `Idempotency-Key`, `If-Match`, CSRF, курсорная пагинация, загрузка файлов напрямую в хранилище.
* **Шелл**: меню по правам роли, глобальный поиск (Ctrl+K), уведомления-колокольчик, смена темы, согласие на ПДн (152-ФЗ), справка `/help`, главная с KPI.
* **CRM**: сделки (таблица, доска, карточка, переходы с чек-листом условий, комментарии, файлы, задачи, история, подписание), организации (ИНН-автоподстановка, дубли, расхождения с ЕГРЮЛ), контакты, задачи, уведомления и их настройки.
* **Конфигурация**: воронки (редактор графа), справочники, импорт (мастер из пяти шагов), отчёты и дашборды, реестр ЕГРЮЛ, интеграции, шаблоны уведомлений.
* **Доступы и подпись**: пользователи, команды, согласования («четыре глаза»), аудит с проверкой цепочки, увольнение (передача дел), удаление ПДн (запрос → блокеры → отсрочка → акт), соглашения ЭДО, настройки и флаги, профиль/сессии/пароль, публичные `/sign`, `/verify`, `/invite`.
* **Дизайн-система**: везде, где в rt-ui есть компонент, используется он (`Button`, `Input`, `Select`, `Chip`, `Badge`, `InlineNotification`, `Modal`, `Drawer`, `TableGrid`, `Tabs`, `Wizard`, `Switch`, `Counter`…). Общие обёртки — `src/lib/ui` (`DataTable`, `Notice`, `StatusChip`, `Card`, `FormDrawer`, поля форм…). Своё (Tailwind) — только раскладка, карточки-секции (в rt-ui нет `Card`) и кликабельные блоки целиком.
* **Адаптив**: таблица ↔ карточки на телефоне, панели на весь экран, проверено на 1440×900, 1280×600, 1024×768, 768×1024, 390×844, 360×640, 844×390; светлая/тёмная тема.

## Покрытие ручек: 193 из 210 (92%)

`node tools/coverage.mjs`, перегенерировано 29.09.2026 — бэкенд с 26.09 добавил ещё несколько ручек (в т.ч. `DELETE` у праздников производственного календаря, пользовательских полей и продуктов, восстановление удалённой организации), интерфейс под большинство прежних пробелов (22.09/25.09) уже построен. Без экрана сознательно (8):

| Ручки | Почему |
|---|---|
| `GET /api/auth/login`, `POST /api/auth/callback`, `POST /api/auth/backchannel-logout` | Поток OIDC: браузер уходит на `/api/auth/login`, вернуться обратно ведёт Keycloak, backchannel вызывает сам Keycloak |
| `GET /health/live`, `GET /health/ready` | Пробы Docker/Caddy |
| `POST /api/v1/integrations/{cms/leads,lms/progress,bitrix/webhook}` | Вебхуки внешних систем, подписаны секретом, которого в браузере быть не должно; на карточке источника есть «паспорт» с примером `curl` |

Появилось на экранах 26.09.2026 (10): `GET /api/imports/entity-types` (поля и форматы типов импорта с сервера, без зашитых списков), `GET /api/imports/{id}/rows` (результат по строкам, вкладки «Ошибки / Предупреждения / Все»), `GET /api/contacts/{id}/products`, `GET/PUT /api/contacts/{id}/learner-profile` и `POST …/reveal` (карточка контакта: просмотр, «Показать», «Изменить»), `GET/PUT/DELETE /api/products/{id}/contacts…` (ответственные в форме продукта), `POST /api/admin/feature-flags` («Новый флаг»), отчёт `lms_users_upload` в «Отчётах»; 409 `CRM-1301` при создании контакта показывает «Такой контакт уже есть» со ссылкой на карточку. С тех пор экраны появились и под весь пакет ручек от 25.09.2026 (предпросмотр шаблона уведомления, карточка команды, продукты сделки, `PATCH /me`, счётчик колокольчика, список кодов событий, переименование воронки, прогресс переноса сделок) — из этого пакета без UI осталась только «переиздать ссылку» (таблица ниже).

Без экрана пока, UI не строился (7):

| Ручки | Что нужно |
|---|---|
| `DELETE /api/admin/teams/{id}` | Кнопка «Удалить» на карточке команды |
| `DELETE /api/custom-field-defs/{id}` | Кнопка «Удалить» на пользовательском поле в конфигураторе полей |
| `DELETE /api/holidays/{id}` | Кнопка «Удалить» на дате производственного календаря (у остальных справочников и воронок кнопка уже есть) |
| `DELETE /api/products/{id}` | Кнопка «Удалить» на карточке продукта |
| `GET /api/organization-licenses/{id}` | Карточка лицензии/договора вуз-вендор-ПО (раздел 4, Треб.1) |
| `POST /api/organizations/{id}/restore` | Кнопка «Восстановить» для администратора — сейчас `OrgCreateDrawer` при дубле по ИНН только сообщает, что восстановить может админ, самой кнопки нигде нет |
| `POST /api/signature-requests/{id}/reissue-link` | «Переиздать ссылку» в карточке запроса на подпись (`docs/backend-issues.md` C-7) |

Не пробел, а слепая зона `tools/coverage.mjs` (2): `GET /api/signature-requests/{id}/file` и `GET /public/sign/{token}/file` попадают в «непокрыто», потому что скрипт ищет только типизированные вызовы `api.GET(...)`; в реальности обе ручки используются — `file_url` из ответа переписывается на текущий origin (`previewUrlForFetch` в `src/lib/features/signing/urls.ts`) и просто фетчится напрямую, без обёртки клиента.
