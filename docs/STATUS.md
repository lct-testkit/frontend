## Проверка кнопок и аудит

`tools/buttons.mjs` открывает каждый экран под каждой ролью и нажимает каждую кнопку, ссылку, вкладку и пункт меню (изменяющие запросы подменяются заглушкой, данные не трогаются); статический аудит кода и живой обход дали список поправок, все сделаны. Осознанно оставлены решения заказчика: read-only справочники и воронки для KAM/HEAD без пункта меню (S2-3); правило «недоступно вашей роли» реализовано не везде (S2-5); диалог перехода теряет черновик при переходе по подсказке-ссылке (S2-12); разрыв с исходным кейсом — отчёты без периода и фильтров по вузу, направлению, продукту, импорт не заводит карточку «лицензия вуза ↔ вендор ↔ ПО» (см. корневой `README.md` → «Соответствие требованиям кейса»).

* **prod** (`"mode": "prod"`): только «Войти» → Keycloak → серверная сессия (httpOnly `crm_sid` + CSRF). Демо-учёток и client secret в prod-конфиге нет. Проверено `node tools/scenarios/lead-prod-login.mjs` (с `APP_URL=http://localhost:8080`).

## Что готово

* **Каркас**: SvelteKit 2 SPA, Svelte 5, TS strict, Tailwind v4 поверх дизайн-системы rt-ui (токены вшиты в тему), 4 темы, шрифт Rostelecom Basis, типизированный клиент по OpenAPI (204 операции), RFC 7807, `Idempotency-Key`, `If-Match`, CSRF, курсорная пагинация, загрузка файлов напрямую в хранилище.
* **Шелл**: меню по правам роли, глобальный поиск (Ctrl+K), уведомления-колокольчик, смена темы, согласие на ПДн (152-ФЗ), справка `/help`, главная с KPI.
* **CRM**: сделки (таблица, доска, карточка, переходы с чек-листом условий, комментарии, файлы, задачи, история, подписание), организации (ИНН-автоподстановка, дубли, расхождения с ЕГРЮЛ), контакты, задачи, уведомления и их настройки.
* **Конфигурация**: воронки (редактор графа), справочники, импорт (мастер из пяти шагов), отчёты и дашборды, реестр ЕГРЮЛ, интеграции, шаблоны уведомлений.
* **Доступы и подпись**: пользователи, команды, согласования («четыре глаза»), аудит с проверкой цепочки, увольнение (передача дел), удаление ПДн (запрос → блокеры → отсрочка → акт), соглашения ЭДО, настройки и флаги, профиль/сессии/пароль, публичные `/sign`, `/verify`, `/invite`.
* **Дизайн-система**: везде, где в rt-ui есть компонент, используется он (`Button`, `Input`, `Select`, `Chip`, `Badge`, `InlineNotification`, `Modal`, `Drawer`, `TableGrid`, `Tabs`, `Wizard`, `Switch`, `Counter`…). Общие обёртки — `src/lib/ui` (`DataTable`, `Notice`, `StatusChip`, `Card`, `FormDrawer`, поля форм…). Своё (Tailwind) — только раскладка, карточки-секции (в rt-ui нет `Card`) и кликабельные блоки целиком.
* **Адаптив**: таблица ↔ карточки на телефоне, панели на весь экран, проверено на 1440×900, 1280×600, 1024×768, 768×1024, 390×844, 360×640, 844×390; светлая/тёмная тема.
