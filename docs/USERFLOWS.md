# Пользовательские потоки и блоки

Составлено 2026-09-21 по `new_spec.md` (ТЗ) и `dop.md` (ПЭП, ИНН, дизайн-система). Это карта потоков и блоков интерфейса: **роль → задача → путь по экранам → какие блоки нужны → какие состояния обязательны**. Блоки B1…B15 описаны в `REBUILD-PLAN.md` (каталог `/dev/blocks`, который их показывал, был доступен только в dev-режиме и удалён перед сдачей — все блоки уже приняты); экраны собираются только из принятых блоков.

## 0. Правила, общие для всех потоков

1. **Один экран — одно главное действие.** Оранжевая кнопка одна: «Новый контакт», «Далее: Квалификация», «Подписать». Остальное — контурные/иконки. На телефоне «создать» — плавающая кнопка.
2. **Все списки одной анатомии:** первая строка (36 px, везде на одной высоте под верхней панелью): вкладки со счётчиком и кнопки страницы справа («Обновить», «Создать») — или, если вкладок нет, «поиск + фильтры + „Фильтры“ + кнопки справа» → вторая строка «поиск + фильтры» (поля без подписи над ними: подпись — плейсхолдер; число включённых фильтров — внутри кнопки «Фильтры») → таблица (телефон — карточки) → подвал со счётчиком и «Показать ещё». Заголовок страницы не показывается (его несёт боковое меню), он остаётся для скринридера. Фильтры живут в адресной строке (ссылка воспроизводит вид). Подробности — REBUILD-PLAN.md §9.
3. **Все карточки одной анатомии:** шапка (назад, название, номер, статусы, факты, действия) → шаги/статус → вкладки → секции-карточки «ключ — значение».
4. **Форма создания/правки — в Drawer справа** (на телефоне на весь экран); **подтверждение — в Modal** с последствиями («будет переназначено 34 сделки»); **многошаговое — мастер** (импорт, увольнение, отправка на подпись, удаление ПДн). Ни один поток не уводит на отдельную «страницу-форму», кроме публичных.
5. **Три состояния обязательны у каждого экрана:** загрузка (скелетон той же высоты), пусто (что делать: одна кнопка), ошибка (человеческая фраза + «Повторить»; для 5xx — код обращения).
6. **Права видны, а не «пропадают»:** недоступное действие — в меню «Ещё» с подписью «Недоступно вашей роли» (пока реализовано в шапке сделки); недоступный раздел — не в меню, по прямой ссылке — экран «Нет доступа».
7. **Ничего необратимого одним кликом:** удаление/увольнение/откат — подтверждение с последствиями; ПДн, акты, подписи — не удаляются, а обезличиваются/аннулируются по правилам ТЗ (§4.8, dop.md §10.7).
8. **Слова, а не коды:** статусы, роли, причины — по-русски (справочники), в таблицах ни одного `snake_case`.

## 1. Роли, вход, куда попадаем

| Роль | Кто | Куда после входа | Видит |
|---|---|---|---|
| KAM | менеджер по вузам | Главная | свои сделки, организации своих сделок, свои задачи, входящие на подпись, справочники (чтение), отчёты «по себе» |
| HEAD | руководитель | Главная (по команде) | всё по команде рекурсивно, передача сделок, импорт, согласования, отчёты по команде, аудит по команде |
| ADMIN | администратор | Главная | всё + воронки, справочники, интеграции, ЕГРЮЛ, ЭДО, пользователи, удаление ПДн, настройки; чтение карточек админом пишет `PII_ACCESS` |
| AUDITOR | аудитор | Журнал аудита | только аудит (чтение + экспорт + проверка цепочки) |
| внешний подписант | сотрудник вуза / физлицо | `/sign/{token}` без входа | один документ и его подпись |
| приглашённый сотрудник | новая учётка | `/invite/{token}` | проверить приглашение → перейти ко входу (пароль задаёт Keycloak) → согласие |

## 2. Потоки

Обозначения: **Экраны** → путь; **Блоки** → из каталога; **Состояния** → что обязано быть нарисовано; §… → раздел ТЗ.

### F0. Вход и первый вход (§3.1, §4.1–4.4)
1. `/` без сессии → экран входа (demo: выбор роли; prod: «Войти» → Keycloak) → возврат на `?next=`.
2. Первый вход или новая редакция политики → **модал согласия на ПДн** (без принятия дальше нельзя; отказ = выход) → запись версии/хэша.
3. Пароль надо сменить → плашка в шапке «Пока вы не смените пароль, часть действий недоступна» → Профиль → Безопасность.
4. Приглашение: `/invite/{token}` → имя, срок ссылки → «Перейти ко входу»; пароль по политике (≥ 12, не из последних 5) задаёт Keycloak → согласие.
- **Блоки:** B14 публичная страница, B9 поля/ошибки, B10 плашка, Modal.
- **Состояния:** ссылка просрочена («Отправить повторно» — у администратора), пароль не прошёл политику (что именно), сессия истекла (тихое обновление, иначе вход с возвратом), Keycloak недоступен.

### F1. Начало рабочего дня (КАМ) — Главная
Плитки (в работе, сумма, SLA под угрозой, мои задачи) → «Требуют внимания» (просроченные SLA) → «Мои задачи» (просроченные красным) → «Недавние» → воронка по шагам. Клик по любому — в сделку/задачу/список с уже включённым фильтром.
- **Экраны:** `/`. **Блоки:** плитка KPI, B6 строки, секция-карточка. **Состояния:** нет сделок (первый день: «Создайте первую сделку»), нет данных для плитки (скелетон, не «0»).

### F2. Завести организацию (dop.md §11)
Организации → «Добавить» → **одно поле «ИНН или название»** (300 мс, локальный реестр ЕГРЮЛ, работает офлайн) → подсказки (краткое имя, ИНН, город, статус; ликвидированные красным, но показаны) → выбор → поля заполнены с пометкой «из реестра», **правятся** → проверка дублей:
- уже есть → не создаём: «Организация в системе. Ответственный: Петров. Активных сделок: 3» + **[Открыть] [Создать сделку]**; если организация не видна КАМ, интерфейс просит обратиться к администратору или руководителю (ручки «запросить доступ» на бэкенде нет);
- есть в удалённых → «удалена, восстановить её может администратор» (ручки восстановления на бэкенде нет);
- другой ИНН, похожее название → мягко: «возможно, филиал: 2 организации».
→ сохранить (снимок ответа реестра, `manual_overrides`).
- **Блоки:** Drawer + B9 формы, поле «поиск-выбор», B10 плашки (предупреждение/ошибка), B8 карточка найденной.
- **Состояния:** ИНН не проходит контрольную сумму (сразу, без сети), реестр пуст/устарел (плашка «Реестр от 12.03», без блокировки), ликвидируется при активной сделке (высокий приоритет, задача юристу).

### F3. Создать сделку (§4.9)
Сделки (или «Новая сделка» из карточки организации/контакта — с предзаполнением) → тип **B2B / B2C** → организация (B2B) или контакт (B2C) → название, продукты, сумма, ответственный → создана в начальном статусе → открывается карточка. Повторная отправка не создаёт дубль (`Idempotency-Key`).
- **Экраны:** список → Drawer «Новая сделка» → карточка. **Блоки:** Drawer, B9, поле-выбор (организация/контакт/продукт), TabsBar (тип). **Состояния:** нет опубликованной воронки для типа, нет прав выбирать ответственного (поле скрыто, назначается по правилу).

### F4. Провести сделку по воронке (§4.9–4.11, dop.md §10.6)
Карточка → лента шагов → **«Далее: X»** → диалог перехода:
- **чек-лист условий (guard):** чего не хватает — обязательные поля, вложения, закрытые задачи — каждое со ссылкой «Заполнить»;
- поля, которые нужны на этом шаге; **комментарий обязателен при возврате назад**; для «Успешно» — сумма и дата, для «Отказ» — причина из справочника + комментарий;
- действие `request_signature` → после перехода открывается вкладка «Подписание».
→ статус, SLA-таймер, история, уведомления обновляются.
- **Экраны:** `/deals/{id}`. **Блоки:** B3 шапка (переходы), B7 лента шагов, B9 диалог, B10 сообщения. **Состояния:** 409 «изменено другим пользователем» (плашка «Обновить», значения конфликтующих полей), 422 «Из статуса A нельзя в B» (текст с причиной), кнопка недоступна по роли (в «Ещё» с подписью), SLA на паузе (статус «заморожена»).

### F5. Работа внутри сделки
Вкладки: **Обзор** (поля, продукты, участники) · **Обсуждение** (Markdown, @упоминания, «внутренний», системные записи) · **Файлы** (загрузка напрямую в хранилище, проверка, лимиты 50 МБ/500 МБ) · **Задачи** (созданные переходом — помечены) · **История** (статусы с длительностью, события) · **Подписание**.
- **Блоки:** B11 вкладки, B6 строки, B8 поля, B9 форма комментария, загрузка файла (DS FileUpload). **Состояния:** файл заражён/на карантине, комментарий отредактирован (метка), нет прав писать (поле скрыто).

### F6. Подписание ПЭП (dop.md §10)
**Инициатор (КАМ/HEAD):** карточка → «Отправить на подпись» → мастер: документ (шаблон или файл) → подписанты и порядок (последовательно/параллельно) → срок → **проверка соглашения ЭДО** (нет — блок «Сначала оформите соглашение» с инструкцией, отправка заблокирована) → отправка.
**Внутренний подписант:** Подписание → входящие → документ (встроенный просмотр, фиксация просмотра) → «Подписать» → **код** (6 цифр, 5 мин, 3 попытки, повтор через 60 с; в демо — подсказка «Подставить») → подписано (протокол, хэш, QR).
**Внешний:** письмо → `/sign/{token}` без входа → просмотр → «Нажимая „Подписать“, вы применяете ПЭП…» → код → подписано → ссылка `/verify/{id}`.
**Проверка:** `/verify` — по номеру подписи или загрузкой файла (сверка хэша).
- **Экраны:** карточка сделки/вкладка «Подписание», `/signing` (входящие, документы, шаблоны), `/signing/{id}`, публичные `/sign`, `/verify`. **Блоки:** B13 мастер, B14 публичные, B10, ввод кода (OTP). **Состояния:** viewed/pending/signed/rejected (причина обязательна)/expired/locked (3 неверных)/void, «документ изменён после отправки» (409), блокировка без соглашения.

### F7. Руководитель: команда (HEAD)
Сделки → фильтр «Ответственный» → «Требуют внимания» (SLA, владелец недоступен) → **массовая передача** (выбор строк → панель действий → «Передать другому» → предпросмотр последствий) → Согласования (four-eyes) → Отчёты по команде → подпись КП.
- **Блоки:** B5 выбор строк + панель действий, B9, Modal-подтверждение. **Состояния:** нет подчинённых, сделки в критичном статусе выделены отдельно.

### F8. Импорт каталога (§4.12)
Импорт → «Новый импорт» → мастер: **загрузка** (.xls/.xlsx/.csv, до 50 МБ) → **профиль** (первые 100 строк, кодировка CP1251/UTF-8, разделитель) → **маппинг** (колонки файла с примерами слева, поля системы справа, автоподбор, пресет) → **проверка (dry-run)** (ок / предупреждения / ошибки, скачать .xlsx с колонкой «Причина ошибки») → **применение** (insert/upsert/update, прогресс) → результат + **«Откатить импорт»**.
- **Блоки:** B13 мастер, DS FileUpload, B5 (превью, ошибки), B10. **Состояния:** битый файл/формулы/zip-бомба (конкретное сообщение), файл слишком большой, откат недоступен.

### F9. Отчёты и дашборды (§4.13)
Отчёты → выбрать отчёт → параметры (период, команда) → **запуск**: лёгкий — сразу, тяжёлый — в очередь с прогрессом → **скачать** (xlsx/pdf/png; ссылка живёт 15 минут, файл 7 дней) → история запусков. Дашборды: свои/общие, виджеты.
- **Состояния:** идёт/в очереди/готов/ошибка/истёк; выгрузка с ПДн требует подтверждения («выгружаю 3 400 записей»).

### F10. Администратор: люди (§4.1–4.8)
Пользователи → «Создать» (ФИО, e-mail, роль, команда; **ADMIN — подтверждает второй админ**) → приглашение. Карточка пользователя: блокировка (причина обязательна, дата авторазблокировки), смена роли (для HEAD нужна команда; последнего админа нельзя), сброс пароля, сессии. **Увольнение** — мастер: что держит (сделки по статусам, задачи, подписки) → преемник → предпросмотр («34 сделки → Иванов; 3 в „Подписание договора“ — критичные») → подтверждение. **Удаление ПДн:** запрос → блокеры (активные сделки, подписи, последний админ) → отсрочка 30 дней с обратным отсчётом и «Восстановить» → исполнение → акт (PDF) — второй админ подтверждает каждое необратимое.
- **Блоки:** B5, B7 карточка, B13 мастера, B10, Modal. **Состояния:** подписи не обезличиваются (блокер `has_signatures` с обоснованием), сотрудник не входил (жёсткое удаление разрешено).

### F11. Администратор: воронки (§4.11)
Воронки → редактор графа (узлы — статусы: имя, тип, цвет, обязательные поля, SLA; рёбра — роли, условия, действия) → **валидация** (один initial, есть терминальный, нет недостижимых и «ловушек», условия ссылаются на существующие поля) → **публикация**. Удаление статуса с живыми сделками → **мастер сопоставления** («27 сделок — куда?», предпросмотр, что с SLA, у кого не заполнены поля) → фоновая задача → статус архивируется.
- **Блоки:** холст графа (xyflow), B9 панель свойств, B13 мастер, B10. **Состояния:** черновик/опубликована, ошибки валидации списком с переходом к узлу, задача сопоставления идёт.

### F12. Настройка: справочники, интеграции, ЭДО, ЕГРЮЛ, шаблоны, настройки
Справочники (продукты, направления, причины отказа, праздники, регионы, поля) — таблица + Drawer. Интеграции (CMS, LMS, Bitrix: состояние, последняя синхронизация, очередь, «паспорт» вебхука). Соглашения ЭДО (сущность: без действующего — подпись контрагента заблокирована). Реестр ЕГРЮЛ (версии выгрузок, загрузка новой). Шаблоны уведомлений. Флаги и настройки.
- **Блоки:** B4/B5 (одинаково везде), B9 Drawer, B10.

### F13. Аудитор
Журнал аудита → фильтры (сущность, актор, период, действие) → строка → детали (`changes`, IP, request_id) → экспорт → **проверка цепочки хэшей**. Только чтение.
- **Блоки:** B4, B5, B7 (детали в Drawer). **Состояния:** цепочка нарушена (красная плашка с записью), пустой период.

### F14. Уведомления и задачи
Колокольчик (красная точка, без цифры) → панель 10 последних (клик — открыть объект и прочитать; «Прочитать все») → «Все уведомления» (фильтры приоритет/сущность) → настройки (каналы по событиям, тихие часы). Задачи: вкладки «Открытые / В работе / Просроченные / Выполненные / Все», группы по сроку, флажок «выполнено», Drawer задачи.
- **Блоки:** B1 колокольчик, B6 строки, B11, B4.

### F15. Профиль
Данные (ключ — значение на одной базовой линии) · Сессии (устройство, IP, последняя активность, «завершить») · Безопасность (смена пароля: текущий обязателен, политика, что произойдёт — «завершим остальные сессии») · тема оформления.
- **Блоки:** B8 (inline), B11, B9.
