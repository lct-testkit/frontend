# Администрирование

**Пользователи и команды.** Учётная запись создаётся администратором; сотрудник получает приглашение. Блокировка немедленно завершает все сессии, сделки остаются за сотрудником и помечаются для руководителя. При увольнении работает мастер передачи дел из трёх шагов: сводка того, что держит сотрудник (сделки, вузы, задачи, запросы подписи); преемник по умолчанию, причина и, при желании, распределение по вузам и отдельным сделкам; подтверждение с отметкой «Понимаю, что действие необратимо». Команды — иерархия («кто чей руководитель»): на ней строится, какие сделки видит HEAD.

![Список команд: название, руководитель, регион](/help/teams.png)

**«Четыре глаза».** Создание администратора и необратимые операции требуют подтверждения вторым администратором — раздел «Согласования».

**Ещё в разделе «Настройка»** (доступно по праву на каждый раздел отдельно, не только администратору): **справочники** (продукты, направления, причины отказа, производственный календарь, поля сделки); **соглашения об ЭДО** — без действующего соглашения внешняя подпись контрагента заблокирована; **интеграции** — состояние синхронизации с сайтом и LMS, у каждого источника есть «паспорт» вебхука с примером запроса; **реестр ЕГРЮЛ** — версии выгрузок для автоподстановки по ИНН; **шаблоны уведомлений** — текст и канал (почта или в системе) для каждого события.

**Удаление персональных данных.** Запрос проверяет блокеры (активные сделки, подписи, законные основания хранения), даёт срок отсрочки и формирует акт об уничтожении. Подписанные документы не обезличиваются.

**Журнал аудита.** Неизменяемый: каждая запись связана хэшем с предыдущей, целостность проверяется кнопкой. Есть фильтры, экспорт и запись об отказах в доступе. Записи попадают в журнал с небольшой задержкой: пока они ждут запечатывания, их число видно над списком; в проверку цепочки и выгрузку такие события не входят.

**Настройки.** Флаги функций и системные параметры; секреты показываются маской.
