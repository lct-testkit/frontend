# Установка: онлайн и офлайн

Глава описывает два способа поставить систему: на сервере с интернетом (из репозитория `deploy`) и в закрытом контуре (из офлайн-пакета релиза).

## Что понадобится

- Docker и плагин `docker compose` на сервере (глава «Обзор и требования»).
- Для установки из интернета: токен GitHub «classic» только с правом `read:packages` (образы `ghcr.io/lct-testkit/*` приватные). Инструкция по токену — файл `docs/ghcr-setup.md` репозитория `deploy`.
- Для офлайн-установки: файлы релиза `rtk-crm-offline-vX.Y.Z.tar.gz`, `rtk-crm-offline-vX.Y.Z.tar.gz.sha256` и `rtk-crm-offline-vX.Y.Z.tar.gz.sigstore.json` со страницы релизов репозитория `deploy`.
- Решение, какое окружение ставите: `demo` (демонстрационное, с демо-учётками на экране входа) или `prod` (боевое). Отличия — в главе «Профили demo и prod».

## Шаги: установка из интернета

1. Один раз подготовьте машину. Скрипт идемпотентен: проверяет Docker, создаёт системного пользователя `deploy` (в группе `docker`: это равно правам root на сервере), каталоги `/srv/rtk-dev`, `/srv/rtk-demo`, `/srv/rtk-prod` и файл подкачки 2 ГБ.

   ```bash
   sudo bash scripts/provision_vm.sh
   ```

2. Войдите в реестр образов под пользователем `deploy`. Пароль читается со стандартного ввода, чтобы токен не попал в историю команд.

   ```bash
   echo <токен> | docker login ghcr.io -u <пользователь-github> --password-stdin
   ```

3. Склонируйте репозиторий и инициализируйте окружение. Команда `--init` создаёт случайные секреты и согласованные с ними настройки в каталоге `/srv/rtk-<окружение>`. Для боевого окружения адрес обязателен:

   ```bash
   git clone https://github.com/lct-testkit/deploy.git /srv/rtk-prod/deploy
   cd /srv/rtk-prod/deploy
   RTK_ENV=prod scripts/deploy.sh --init --host crm.example.local --profile prod
   ```

   Для демонстрационного окружения: `RTK_ENV=demo scripts/deploy.sh --init --host crm.example.local`. Если на той же машине нужно второе окружение (режим TLS `off`), порты разводятся флагом `--port-offset`: `RTK_ENV=dev scripts/deploy.sh --init --port-offset 100`.

4. Запустите выкладку: скрипт скачает образы, поднимет стек и проверит его дымовым тестом.

   ```bash
   RTK_ENV=prod scripts/deploy.sh
   ```

5. Для демонстрационного окружения (и только для него) залейте моковые данные. В `prod` скрипт откажется работать.

   ```bash
   bash scripts/seed_demo.sh --env-file /srv/rtk-demo/.env --images-env /srv/rtk-demo/.env.images --project rtk-demo
   ```

6. Автообновление включается только для `demo` и `dev` (раз в 5 минут). Боевое окружение автоматически не обновляется — это сделано намеренно.

   ```bash
   sudo bash scripts/install_autodeploy.sh demo
   ```

## Шаги: офлайн-установка

1. Проверьте целостность архива. Желательно ещё проверить подпись — для этого нужна утилита `cosign`.

   ```bash
   sha256sum -c rtk-crm-offline-vX.Y.Z.tar.gz.sha256
   cosign verify-blob rtk-crm-offline-vX.Y.Z.tar.gz.sha256 \
     --bundle rtk-crm-offline-vX.Y.Z.tar.gz.sha256.sigstore.json \
     --certificate-identity-regexp '^https://github.com/lct-testkit/deploy/' \
     --certificate-oidc-issuer https://token.actions.githubusercontent.com
   ```

   Если архив нарезан на части (лимит вложения 2 ГиБ), склейте его перед проверкой: `cat rtk-crm-offline-*.tar.gz.part-* > rtk-crm-offline.tar.gz`. В полностью изолированной сети проверка подписи требует доверенного корня Sigstore; если его нет, сверьте файл `.sha256` с копией, полученной по независимому каналу.

2. Перенесите архив на изолированную машину (Docker там уже стоит), распакуйте и запустите установщик:

   ```bash
   tar xzf rtk-crm-offline-vX.Y.Z.tar.gz && cd rtk-crm-offline-vX.Y.Z
   bash install.sh --profile prod --host crm.example.local
   ```

   В терминале без флагов установщик задаст вопросы (окружение, адрес, TLS, шрифты, моковые данные), покажет сводку и спросит подтверждение. Без терминала и без флагов берутся значения по умолчанию: `demo`, `localhost`, моковые данные включены.

3. Что делает установщик по порядку: сверяет контрольные суммы (при расхождении останавливается до загрузки образов), проверяет подпись архива, если рядом лежат файлы подписи и установлен `cosign`, загружает образы (`docker load`), создаёт секреты, поднимает стек без обращения в сеть, запускает дымовой тест и, если выбрано, загружает моковые данные.

   | Флаг | Что задаёт |
   | --- | --- |
   | `--profile demo\|prod` (или `--env`) | Окружение. По умолчанию `demo`. Для `prod` нужен `--host` |
   | `--host` | Имя или IP, по которому открывают систему |
   | `--tls acme\|internal\|off` | Режим TLS. Глава «TLS и домен» |
   | `--fonts <каталог>` | Каталог со шрифтами Rostelecom Basis (`*.woff`), если они не вошли в пакет |
   | `--seed` и `--no-seed` | Моковые данные (только `demo`, там включены по умолчанию) |
   | `--port-offset N` | Сдвиг портов для нескольких стендов на одной машине (только `--tls off`) |
   | `--open-firewall` | Открыть порты 80, 443, 8333 в ufw, если он включён |
   | `--skip-dns-check` | Не проверять, что имя указывает на этот сервер |
   | `--reconfigure` | Не устанавливать, а сменить адрес и режим TLS у готового стенда |
   | `--registry` | Поднять внутренний реестр образов на `localhost:5000` |
   | `--monitoring` | Поднять Prometheus и Grafana |
   | `--no-start` | Только проверить, загрузить образы и создать настройки, стек не запускать |
   | `--yes` | Ничего не спрашивать |

4. Если `compose/.env` уже существует (повторный запуск), окружение и адрес берутся из него, а секреты не трогаются. Сменить окружение на другое можно только новой установкой: пароли базы в томах привязаны к прежнему `.env`.

5. Для обновлений без ручного переноса архивов на каждую машину в контуре поднимите внутренний реестр: `bash install.sh --registry`. На остальных машинах получите ссылки на образы из него командой `python3 scripts/render_env_images.py --mode registry --registry registry.local:5000 > /srv/rtk-demo/.env.images`.

## Как проверить

Дымовая проверка одинакова для обоих путей. Она проверяет балансировщик, готовность API, выдачу клиента, импорт realm Keycloak, ключи входа и то, что защищённые адреса закрыты без сессии:

```bash
bash scripts/smoke.sh http://localhost:8080
```

В режиме `internal` (самоподписанный сертификат) добавьте `--insecure`. Установщик пишет итоговый адрес строкой «готово: …». Откройте его в браузере: должен появиться экран входа.

## Что не работает в этой сборке

- Код подписи по СМС уходит на сервис-имитатор `sms-gateway-mock`, настоящего оператора нет.
- Telegram не подключён, антивирусная проверка файлов — заглушка.
- Путь через Helm и Kubernetes экспериментальный.
- Шрифты Rostelecom Basis лицензионные и в образ не входят: без них интерфейс работает на запасной гарнитуре, а `smoke.sh` печатает предупреждение (не ошибку). Положите файлы `*.woff` в каталог шрифтов стенда (глава «TLS и домен»).

## Если не получилось

- `required variable API_IMAGE is missing` — не передан файл со ссылками на образы: выполните `python3 scripts/render_env_images.py > .env.images` или запускайте через `scripts/deploy.sh`.
- `unauthorized` при скачивании образов — токен истёк или не выполнен вход: повторите шаг 2.
- Остальное — в главе [«Неполадки»](?s=admin-troubleshooting).
