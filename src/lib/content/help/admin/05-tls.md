# TLS и домен

Глава объясняет три режима защищённого соединения, что проверяет установщик перед запуском и как сменить адрес стенда после установки.

## Что понадобится

- Имя или IP-адрес, по которому пользователи будут открывать систему.
- Для режима `acme`: публичное доменное имя, запись DNS типа A на этот сервер и порты 80 и 443 доступными из интернета.
- Для режима `internal`: ничего снаружи, но на компьютеры пользователей придётся установить корневой сертификат (ниже).

## Три режима

Режим выбирается при установке флагом `--tls` (или вопросом установщика). По умолчанию он выводится из адреса: домен даёт `acme`, IP-адрес и внутренние имена (`.local`, `.lan`, имя без точки) — `internal`, `localhost` — `off`.

| Режим | Кому | Что происходит |
| --- | --- | --- |
| `acme` | Публичный домен | HTTPS на порту 443. Сертификат Let's Encrypt выпускается автоматически при первом обращении (проверка по HTTP через порт 80), обычный http перенаправляется на https |
| `internal` | Закрытый контур, IP, внутренние имена | HTTPS на порту 443 с самоподписанным сертификатом Caddy |
| `off` | Локальная проверка, тест, несколько стендов на одной машине | `http://ХОСТ:8080` и `https://ХОСТ:8443` с самоподписанным сертификатом; порты сдвигает `--port-offset` |

В режимах `acme` и `internal` порты 80, 443 и 8333 (адреса файлов) фиксированы и флаг `--port-offset` недопустим: такой стенд на машине один. Обычный http на порту 8080 в этих режимах слушает только `127.0.0.1`. Docker публикует порты в обход ufw, поэтому всё, что не должно быть видно снаружи, привязывается к `127.0.0.1`, а не полагается на файрвол.

Сертификаты лежат в томе `caddy_data`. Не удаляйте его без нужды (`docker compose down -v`): у Let's Encrypt есть лимит на число выпусков сертификатов для одного домена.

## Что проверяет установщик

Перед загрузкой образов в публичных режимах установщик проверяет, что порты 80, 443 и 8333 свободны, что имя резолвится и указывает на внешний адрес сервера (для `acme`; отключается флагом `--skip-dns-check`), что доступен Let's Encrypt и что ufw пропускает нужные порты. Если ufw закрывает порты, установщик печатает готовые команды `ufw allow …`, а с флагом `--open-firewall` открывает их сам. При любой проблеме установка останавливается без изменений.

## Шаги

### Корневой сертификат для режима internal

Чтобы браузеры не предупреждали о самоподписанном сертификате, установите корневой сертификат Caddy на компьютеры пользователей. Команду печатает установщик; она копирует сертификат из контейнера:

```bash
docker compose -f compose/docker-compose.yml --env-file compose/.env --env-file compose/.env.images cp caddy:/data/caddy/pki/authorities/local/root.crt ./caddy-root.crt
```

Для окружений, поставленных через `scripts/deploy.sh`, замените пути на `--env-file /srv/rtk-<окружение>/.env --env-file /srv/rtk-<окружение>/.env.images` и добавьте `-p rtk-<окружение>`.

### Сменить адрес или режим после установки

Не переустанавливайте стенд: секреты и данные остаются нетронутыми.

```bash
bash scripts/set_host.sh --host crm.example.ru --tls acme
```

Та же операция через установщик: `bash install.sh --reconfigure --host crm.example.ru --tls acme`. Для окружений `scripts/deploy.sh` добавьте `--env-file /srv/rtk-<окружение>/.env --images-env /srv/rtk-<окружение>/.env.images --project rtk-<окружение>`. Флаг `--no-restart` только перепишет настройки и напечатает команды для ручного применения.

Зачем нужен отдельный скрипт: настройки входа (realm Keycloak) импортируются один раз, при создании базы, поэтому правка файла у работающего стенда ничего не меняет, а вход на новом домене падает с `invalid_redirect_uri`. Скрипт делает три вещи: переписывает `.env` (старая копия сохраняется как `.env.bak-<время>`), прописывает допустимые адреса клиента `crm-bff` прямо в базе Keycloak и пересоздаёт сервисы с перезапуском Keycloak. Старые адреса в списке допустимых остаются; при необходимости уберите их в консоли Keycloak.

### Шрифты Rostelecom Basis

Шрифты лицензионные и не входят ни в репозиторий, ни в образ `web`. Без них интерфейс работает на запасной гарнитуре. Положить файлы `*.woff` можно тремя способами: при сборке пакета (`scripts/build_offline_bundle.sh <версия> --fonts <каталог>`), при установке (`install.sh --fonts <каталог>`) или на работающем стенде — достаточно положить файлы в каталог `compose/fonts/`: он подключён к Caddy, перезапуск не нужен. Релизный пакет из CI собирается без шрифтов, их передают при установке.

## Как проверить

```bash
bash scripts/smoke.sh https://crm.example.ru
```

Для `internal` добавьте `--insecure`. Откройте адрес в браузере: для `acme` должен быть доверенный сертификат без предупреждения, для `internal` предупреждение исчезает после установки корневого сертификата. Предупреждение браузера о самоподписанном сертификате в режиме `off` и до установки корневого сертификата — ожидаемое поведение, а не ошибка.

## Если не получилось

- `invalid_redirect_uri` при входе на новом адресе — адрес менялся без `set_host.sh`. Выполните скрипт, как описано выше.
- Установщик остановился на проверке DNS — имя не указывает на внешний адрес этого сервера. Исправьте запись или, если уверены, используйте `--skip-dns-check`.
- Установщик пишет, что нет доступа к Let's Encrypt, — в закрытом контуре используйте `--tls internal`.
