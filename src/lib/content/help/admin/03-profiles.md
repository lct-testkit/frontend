# Профили demo и prod

Слово «профиль» в документации встречается в трёх смыслах. Глава объясняет разницу и показывает, что именно меняется между демонстрационным и боевым окружением.

## Что понадобится

Установка из главы [«Установка: онлайн и офлайн»](?s=admin-install) и понимание, для чего вы ставите систему: показать её (demo) или работать в ней (prod).

## Три «профиля»

| Что | Где задаётся | Значения |
| --- | --- | --- |
| Профиль установки | Флаг `--profile` (или `--env`) у установщика и у `scripts/deploy.sh --init` | `demo` или `prod` |
| `APP_PROFILE` | Файл `.env`, его читает серверное приложение | `dev`, `demo`, `prod`. Установщик пишет `demo` или `prod`; `dev` — режим машины разработчика (по умолчанию в `.env.example` самого бэкенда) |
| `APP_MODE` | Файл `.env`, его читает только образ `web` и отдаёт клиенту через `/config.json` | `demo` или `prod` |

Выбрав профиль установки `prod`, вы получаете `APP_PROFILE=prod` и `APP_MODE=prod` сразу: вручную менять их не нужно.

## Что меняется

| | demo | prod |
| --- | --- | --- |
| Экран входа | Показывает карточки демо-учёток | Только вход через Keycloak, демо-учёток в клиенте нет |
| `/config.json` клиента | Содержит демо-логины и секрет клиента Keycloak | Секрет не публикуется |
| Моковые данные | Можно загрузить (`--seed`) | Недоступны, скрипт отказывается работать |
| Swagger UI (`/api/docs`) | Открыт | Закрыт (схема API остаётся доступной) |
| Вход по `Authorization: Bearer` | Для всех ролей | Только для сервисной роли `INTEGRATION` |
| Код подтверждения подписи в ответе (`debug_code`) | Возвращается | Выключено |
| Автоподстановка по ИНН | Работает заглушка | Только локальный реестр ЕГРЮЛ и уже подтверждённые организации |
| Секреты | Случайные, создаются установщиком | Случайные; приложение не стартует с демонстрационными значениями `SIGNATURE_SERVER_SECRET`, `KEYCLOAK_*_SECRET`, `S3_*` и `CRM_APP_PASSWORD`, а `scripts/deploy.sh` с `RTK_ENV=prod` отказывается запускаться с демо-секретами |
| Пользователи Keycloak | Демо-пользователи остаются в realm | Демо-пользователи остаются в realm и **их нужно удалить вручную** (глава «Keycloak и пользователи») |

Внимание: стенд `demo` на публичном адресе показывает на экране входа и в `/config.json` демо-логины и секрет клиента Keycloak. Не открывайте такой стенд в интернет. Для боевого использования ставьте `--profile prod`.

## Шаги: как выбрать

1. Показ, пилот в закрытой сети без реальных данных — `demo`: `bash install.sh --profile demo --host crm.example.local --seed`.
2. Любая работа с реальными данными — `prod`: `bash install.sh --profile prod --host crm.example.local` (или `RTK_ENV=prod scripts/deploy.sh --init --host crm.example.local --profile prod`).
3. Менять окружение у установленного стенда нельзя: секреты и пароли базы в томах привязаны к прежнему `.env`. Нужна новая установка.

## Как проверить

Откройте экран входа. Для `demo` на нём предлагаются карточки учётных записей, для `prod` — только вход через Keycloak. Для `prod` дополнительно проверьте, что Swagger закрыт:

```bash
curl -i http://localhost:8080/api/docs
```

Ожидается, что интерфейс Swagger не откроется (сервер вернёт ошибку); сама схема API остаётся доступной.

## Если не получилось

- После установки `prod` на экране входа всё равно демо-карточки — проверьте `APP_MODE` в `.env`: должно быть `prod`. После правки пересоздайте сервис `web`.
- API в `prod` не стартует — в журнале (`logs api`, глава «Мониторинг и логи») ищите отказ из-за демонстрационных значений секретов; пересоздайте окружение командой `--init`.
