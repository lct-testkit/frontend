# Мониторинг и логи

Глава показывает, где смотреть состояние системы, как читать логи и как включить Prometheus и Grafana с готовыми дашбордами.

## Что понадобится

- Доступ к серверу и к `.env` стенда.
- Для дашбордов: возможность поднять дополнительные сервисы (профиль `monitoring`).

## Что есть всегда

| Что | Где | Что показывает |
| --- | --- | --- |
| Адреса состояния | `/health/live` и `/health/ready` | Жив ли API и отвечают ли база, Redis, Keycloak, хранилище файлов и очередь |
| Плашки в интерфейсе | Экран «Интеграции» под администратором | То же состояние зависимостей |
| Журналы сервисов | Журналы контейнеров | Сообщения приложения и служб (формат JSON, уровень `INFO`) |

Журналы хранит Docker в формате `json-file`: 10 МБ на файл и 3 файла на контейнер, затем самые старые вытесняются. Этого хватает для недавней истории; для долгого хранения собирайте журналы во внешнюю систему.

Смотреть журнал сервиса (например, `api`):

```bash
docker compose -p rtk-demo -f compose/docker-compose.yml --env-file /srv/rtk-demo/.env \
  --env-file /srv/rtk-demo/.env.images logs -f api
```

Метрики Prometheus отдают `api` (порт 8000 внутри сети), `worker` (порт 9101, задаётся `WORKER_METRICS_PORT`) и Keycloak (`/auth/metrics`). Наружу, через `caddy`, адрес `/metrics` не публикуется: он отвечает как отсутствующая страница.

## Шаги: включить дашборды

Сборщик метрик не поднимается по умолчанию. Включается профилем `monitoring`:

```bash
docker compose -p rtk-demo -f compose/docker-compose.yml --env-file /srv/rtk-demo/.env \
  --env-file /srv/rtk-demo/.env.images --profile monitoring up -d
```

При установке офлайн-пакета можно сразу добавить флаг `--monitoring`. Что поднимается:

- Prometheus: история метрик в томе `prometheus_data`, срок хранения — `PROMETHEUS_RETENTION` в `.env` (по умолчанию 15 дней). Он собирает метрики с каждой реплики `api` и `worker` отдельно: счётчики живут в памяти процесса, и общий адрес на все реплики искажал бы графики.
- Grafana по адресу `/grafana/` на том же сайте. Вход — `GRAFANA_ADMIN_USER` и `GRAFANA_ADMIN_PASSWORD` из `.env` (установщик создаёт пароль случайным). Гостевой просмотр без пароля включается переменной `GRAFANA_ANONYMOUS_VIEWER=true`: тогда любой, кто открыл `/grafana/`, видит дашборды (только чтение). Метрики при этом становятся публичными: включайте только на демонстрационном стенде. По умолчанию выключено.

Дашборды лежат в репозитории и подгружаются при старте, вручную их создавать не нужно:

- «API — здоровье и производительность»: запросы в секунду, доля ошибок, задержки p50, p95 и p99 с порогом 300 мс. Это стартовая страница Grafana;
- «Бизнес-метрики и эксплуатация»: очередь и фоновые задачи с их длительностью, SLA, отчёты, импорт, кэш графа воронки, аудит, доступность зависимостей.

## Метрики

Приложение отдаёт метрики с префиксом `crm_`:

| Метрика | Что означает |
| --- | --- |
| `crm_http_requests_total`, `crm_http_request_duration_seconds` | Число и длительность HTTP-запросов по маршрутам. Целевое значение p95 для переходов по сделке — 300 мс |
| `crm_http_errors_total` | Ошибочные ответы по коду каталога ошибок (глава «Коды ошибок») |
| `crm_queue_depth` | Число задач в очереди |
| `crm_background_task_duration_seconds`, `crm_background_tasks_total` | Длительность и итог фоновых задач |
| `crm_import_duration_seconds`, `crm_import_rows_total` | Время и строки импорта |
| `crm_sla_violations_total`, `crm_sla_breaching_deals` | Нарушения SLA и число сделок с нарушенным сроком |
| `crm_cache_requests_total` | Обращения к кэшу (для доли попаданий) |
| `crm_webhook_deliveries_total` | Доставки подписок на события по итогу |
| `crm_reports_in_progress` | Число отчётов в работе (лимит `REPORTS_MAX_CONCURRENT`) |
| `crm_audit_records_total` | Записи аудита |
| `crm_dependency_up` | Доступность зависимости по данным `/health/ready` |
| `crm_signature_complete_seconds` | Длительность завершения подписания на последней подписи |
| `crm_gc_pause_seconds` | Паузы сборщика мусора |

Пороги срабатывания в поставке не заданы (кроме 300 мс на дашборде задержек), определяйте их по вашему обычному уровню.

## Как проверить

- `curl http://localhost:8080/health/ready` возвращает `"status":"ok"`.
- После включения профиля откройте `/grafana/`, войдите: на главной должен быть дашборд «API — здоровье и производительность» с живыми графиками.
- Проверьте, что снаружи `/metrics` недоступен.

## Если не получилось

- Адрес `/grafana/` не открывается — профиль `monitoring` не запущен: выполните команду из раздела «Шаги: включить дашборды».
- Графики пустые — подождите несколько минут после запуска профиля, сбор метрик идёт с интервалом.
- Остальное — в главе [«Неполадки»](?s=admin-troubleshooting).
