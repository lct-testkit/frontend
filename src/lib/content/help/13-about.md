# О проекте

**Команда «Тесткит».** RTK School CRM — внутренняя CRM ИТ Школы Ростелекома для продаж образовательных программ вузам и физическим лицам. Её сделала команда «Тесткит»: [страница команды на GitHub](https://github.com/lct-testkit) — путеводитель по репозиториям со ссылками на всё ниже.

**Из чего собрано.** Веб-клиент на SvelteKit и Svelte 5; API на FastAPI с PostgreSQL, Redis и фоновым воркером; Keycloak для входа; файловое хранилище SeaweedFS (S3). Интерфейс — на своей дизайн-системе rt-ui (см. главу «Дизайн-система»). Всё упаковано в Docker; для сервера есть готовые образы, Helm-чарт, автодеплой и офлайн-бандл со всеми образами для закрытого контура.

**Где посмотреть.**

* [README продукта](https://github.com/lct-testkit/.github#readme) — запуск, роли, соответствие требованиям кейса, библиотеки, ранбук;
* [бэкенд](https://github.com/lct-testkit/backend#readme) — API, модель данных, права, аудит; Swagger UI — на `/api/docs` у стенда;
* [веб-клиент](https://github.com/lct-testkit/frontend#readme) — блоки интерфейса, редактор воронки, интеграция с Битрикс24;
* [rt-ui](https://github.com/lct-testkit/rt-ui#readme) — дизайн-система: компоненты, темы, сверка с оригиналом;
* [deploy](https://github.com/lct-testkit/deploy#readme) — конвейер поставки, RUNBOOK, релизы.

**Как проверяли.** При каждом изменении клиента автоматически идут линтеры кода и стилей, проверка типов, тесты, сборка, контроль размера бандла, аудит зависимостей, сверка типов API с контрактом бэкенда и сканер уязвимостей и секретов. Обходы всех экранов и кнопок под всеми ролями и размерами (`tools/qa-all.mjs`, `tools/buttons.mjs`, `tools/taps.mjs`) требуют живого стенда и в автоматическую проверку не входят: их запускают вручную перед сдачей. Интеграция с Битрикс24 проверена на живом портале.

**Покрытие API интерфейсом.** На 20.10.2026 из 287 методов API 262 вызываются из экранов (проверка `node tools/coverage.mjs`; остальные — машинные вызовы или методы, экран для которых ещё не сделан). Число считается по схеме API и меняется с каждым спринтом; список и пояснения — в файле `docs/STATUS.md` репозитория клиента.

## Что подключено по-настоящему, а что имитация

Этот раздел отвечает на вопрос «что из описанного в системе работает на настоящих внешних сервисах». Всё, что названо имитацией, подключается заменой одного модуля или настройкой, переписывать систему не нужно.

| Что | Как работает сейчас | Как подключить настоящее |
| --- | --- | --- |
| Антивирус | Заглушка: всегда отвечает «чисто». Реально проверяются расширение, сигнатура (первые байты) и контрольная сумма файла | Заменить модуль проверки файлов на подключение к антивирусному сканеру |
| СМС с кодом подписи | Уходит на тестовый шлюз-имитатор (`sms-gateway-mock` в составе стенда) | Заменить шлюз на клиент настоящего СМС-провайдера |
| Почта | Настоящая: письма уходят, когда администратор задал почтовый сервер (`SMTP_HOST` и соседние переменные). Без него письма остаются в очереди | Руководство администратора, глава «Почта и SMTP» |
| Telegram | Канал уведомлений объявлен, но не подключён: сообщения не отправляются | Нужен отдельный модуль доставки сообщений |
| Битрикс24 | Исходящие события (создание и смена статуса сделки) уходят на портал и проверены на живом портале; входящий поток принимается по упрощённому контракту, а не по настоящим событиям портала | Раздел «Интеграции» и руководство администратора |
| Электронная подпись | Простая электронная подпись (ПЭП), а не квалифицированная: не заменяет КЭП там, где закон требует её | Квалифицированная подпись в системе не реализована |
| Реестр ЕГРЮЛ | Локальная выгрузка реестра в системе, автоподстановка по ИНН работает без интернета | Новые версии выгрузки загружает администратор |
| Развёртывание в Kubernetes (Helm) | Экспериментальный путь: чарт проверяется статически, но установка в кластер в автоматической проверке не гоняется. Основной путь — Docker Compose | Руководство администратора, глава «Установка: онлайн и офлайн» |
| Резервные копии | Копия снимается скриптом перед выкладкой и вручную; расписания в поставке нет | Руководство администратора, глава «Резервные копии и восстановление» |

**Материалы третьих лиц.** Шрифт Rostelecom Basis и фирменные материалы дизайн-системы принадлежат Ростелекому и в репозитории не хранятся. Исходный код проекта распространяется по лицензии Apache-2.0; шрифт и фирменные материалы Ростелекома в неё не входят.
